# 세모 게임실

4학년 학생들이 종이에 그린 게임 기획서(수학 「삼각형」 + 「평면도형의 이동」)를
**기획서의 규칙과 숫자 그대로** 플레이할 수 있게 옮긴 STEAM 수업용 웹앱.
수업 흐름 : 학생 기획안 → 교사가 AI로 구현 → AI 피드백(기획 학생에게 보내는 편지) → 학생 디버깅·게임 체험·수정(활동지) → 최종안.
AI 피드백은 편지 한 통뿐이다. 편지의 "조금 아쉬울 수 있는 곳"은 정답이나 수치 없이, 어디를 보면 될지와 질문만 주는 비계다.

5모둠 전부 제출, 모둠마다 게임 하나 — A·B·C(2026-09-30 스캔), D·E(2026-10-01 스캔, 앞뒤 스캔).

## 게임 5종

| # | 게임 | 기획 (모둠) | 삼각형 개념 |
| --- | --- | --- | --- |
| 1 | 미션 삼각형 돌리기 | 아야어여우유어이 (A) | 예각·직각·둔각 구별 + 90° 돌리기. 쉬움 6개 → 보통 30개, 종류별 번호 |
| 2 | 피자 자르기 | 키위 맛 우유 (B) | 꼭짓점 세 곳을 찍어 예각·둔각 조각 만들기. 세 각이 화면에 나온다 |
| 3 | 물고기 잡기! | 잼민이 아닌데요? (C) | 빛나는 지느러미 삼각형 구별. 바다·심해 속·강, 한 번 틀리면 실패 |
| 4 | 퍼즐을 맞춰라! | 안경 ⌐o-o (D) | 문장이 말한 삼각형으로만 집·산·우산·배·물고기 모양 칸 채우기. 끌어다 90°씩 돌려 맞춤, 한 문제 30초 |
| 5 | 칠각 게임 | 사람들 (E) | 네모 틀을 한 가지 삼각형으로만 칠교처럼 채우기. 목숨·난이도·힌트 상점·포인트, 채운 % 로 통과 |

## 편지에서 짚은 곳 (1차)

| 게임 | 아쉬울 수 있는 곳 (비계) | 테스트에서 확인한 근거 (학생에게는 안 보여 줌) |
| --- | --- | --- |
| 미션 삼각형 돌리기 | 틀려도 큰일이 없음 / 「왼쪽으로 4칸」 모양 | 번호만 보고 찍어도 목표 하나에 평균 1번 틀리면 찾음 / 1칸 90°라 4칸 = 360° |
| 피자 자르기 | 한쪽 손님이 유난히 쉬움 / 뒤로 갈수록 같음 | 아무렇게나 세 점 → 둔각 69~70% |
| 물고기 잡기! | 심해 지느러미가 직각과 비슷 + 한 번에 실패 / 잡을수록 같음 | 심해 예각 ≤84°, 둔각 ≥96° |
| 퍼즐을 맞춰라! | 칸 꼭짓점 글씨가 답을 알려 줌 / 30초가 빠듯할 수 있음 | 한 문제에 조각 3~4개, 돌리기 4~10번 |
| 칠각 게임 | 10라운드 다 통과해도 50P에 못 미침 / 잘못된 삼각형 두 번이면 끝 | 10라운드 모두 통과 = 20P, 0P에서 두 번 틀리면 −20P |

수치는 `scripts/smoke_test.js` 자동 플레이에서 나온 값(`scripts/measure.json`).

## 2차 — 디버깅 페이퍼 반영 (게임 1·2·3, 2026-10-01)

페이퍼 12장(게임마다 4장). 원본 PDF는 `data/`(비공개), 이름 칸을 가린 이미지는 `source_images/g{n}_paper_{k}.jpg` 로 「기획안 → 디버깅 페이퍼」 탭에 붙였다.
학생 실명은 저장소·사이트 어디에도 쓰지 않는다.

| 게임 | 반영 | 빼거나 조정한 것 |
| --- | --- | --- |
| 미션 삼각형 돌리기 | 5번 틀리면 「틀려서 처음으로 초기화됩니다」(기획자) · 쉬움→보통(15개, 새로)→어려움(1차의 30개) · 1~5칸 버튼 | 게임 이름 바꾸기(패스) · 「목숨 5개, 틀리면 2개씩」은 기획자 의견과 겹쳐 기획자를 따름 |
| 피자 자르기 | 난이도별 시간(쉬움 2분·보통 1분30초·어려움 1분) · 4번째 손님부터 직각 주문 · 7번째부터 여러 조각 주문(「둔각 하나, 예각 두 개 주세요」, 선생님 제안) · 조각 최소 넓이 5% · 피자 3종 · 결과 창 「나가기」 | 각도기(패스 — 눈으로 가려 보는 학습이 사라짐) |
| 물고기 잡기! | 목숨 바다 4·강 3·심해 2 · 심해 속도 120→180 | 코인으로 낚싯대 업그레이드(패스 — 범위가 큼) |

편지는 `LETTERS[n]` 에 2차를 더했다(이번에 바꾼 것 / 이번에 내가 정한 것 / 아쉬울 수 있는 곳 하나). 활동지는 최신 편지의 짚은 곳과 2차 값을 인쇄한다.

## 구조

```
index.html        홈(게임 포스터 5장 + 모둠 제출 현황) + 게임 화면 + 모달(기획안·편지)
worksheet.html    디버깅 활동지 인쇄본 (A4, 안내 1 + 게임 5). 게임 쪽마다 편지에서 짚은 곳을 인쇄
css/app.css       공통 화면 · 편지
css/games.css     게임별 무대
js/core.js        효과음 · 삼각형 기하(각으로 삼각형 만들기, 각 재기, 판정) · GameBase · 화면 전환
js/data.js        게임 정보 · 홈 포스터 SVG · 모둠 · 편지(LETTERS: body / mine 내가 정한 것 / hints 아쉬울 수 있는 곳)
js/pieces.js      삼각형 조각 끌기·돌리기·쟁반 배치·모양 비교 (게임 4·5 공용)
js/games/*.js     게임 하나당 한 파일. 값은 맨 위 paramSpec 한 곳에만
data/             원본 스캔 PDF (gitignore — 지운 이름 흔적이 있어 공개하지 않음)
source_images/    게임별 기획서 쪽 (90° 회전 보정, g1 1쪽 지운 닉네임 흔적 가림, g4·g5 연필 대비 보정, g5 2쪽은 규칙 뒷장)
extracted_games.md 기획서 분석서
scripts/          smoke_test.js (jsdom 자동 플레이) · browser_check.js (Chrome 헤드리스 점검)
```

바닐라 HTML/CSS/JS. `python -m http.server` 로 열면 된다. 글꼴(Pretendard·JetBrains Mono)만 CDN이고 없어도 시스템 글꼴로 뜬다.

## 원칙

- 기획서 수치는 고치지 않는다. 기획서에 없는 값만 채우고 편지의 "내가 정한 것"에 적었다.
- 게임 안에 밸런스 조절 UI는 없다. 값은 기획 학생이 활동지 ③에 적는다.
- 최종안: 활동지 스캔 → `paramSpec.orig`·규칙 수정 → 활동지 "지금 값" 갱신 → 재배포 → `LETTERS[n]`에 최종판 편지 추가.

## 검증

```
python -m http.server 8765
NODE_PATH=<jsdom·puppeteer-core 설치 폴더>/node_modules node scripts/smoke_test.js
NODE_PATH=<...>/node_modules node scripts/browser_check.js <스크린샷 폴더>
```

- jsdom: 세 게임 클리어·실패 경로, 쉬움→보통 전환, 점수 규칙, 맵 3개, 게임 나가면 타이머 정리.
- Chrome(1366×657 크롬북, 1920×1080 전자칠판): 세로 스크롤 0, 실제 마우스 클릭(삼각형 선택·버튼·가위질·낚시·조각 끌어 놓기), 모달, Esc 동작, 콘솔 오류 0, 인쇄 쪽수(활동지 6쪽).
